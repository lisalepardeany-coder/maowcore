# Dev notes: the 3.5.0 merge

## Why there was a merge

After v3.2.4 (975bc23, 2026-05-31) MaowCore was developed in two places:

- **GitHub `main`** (9 commits, up to 24b41aa, 2026-07-27): automod v2, leveling,
  economy, community, modmail, live alerts, setup templates, and the new SvelteKit
  dashboard (`dashboard/`). The classic dashboard was moved to `public/legacy/`.
- **The home PC** (never committed until 92b5b5b): YouTube cookies and streaming,
  MaowCore Portable (`desktop/`), status monitor, pets, routines, themes, and the
  Pterodactyl egg, among others. About 100 files.

3.5.0 is a real three-way merge with v3.2.4 as the base, so both histories stay
intact.

## How the conflicts were resolved

| File | Decision |
|---|---|
| `package.json` | PC's newer dependency versions plus GitHub's `dashboard:*` scripts. |
| `lib/automod.js` | GitHub's engine (scam, anti-nuke, raid shield, ladder) is the base. Added from the PC: `isShouting` (`capsFilter`), `hostAllowed` for the link allow-list (a substring test let `evil.com/?youtube.com` through), whole-word matching in `matchesWordFilter` (plain words only; `re:` patterns unchanged), and a once-a-minute raid alert. Both config names work: `mentionSpam`/`mentionFilter`, `dupeSpam`/`dupFilter`. |
| `escalate()` | Ladder first; if it has no step for this count, fall back to `mod-tools.applyWarnRules`. Exactly one acts, so `/warn` and automod hits can't punish twice. |
| `commands/automod.js` | GitHub's `toggle`/`set` structure. The PC's caps filter and "filter hits give a warning" (`escalateAutomod`) became toggle choices. A toggle also flips the old key name, and `/automod show` reads both. |
| `commands/warn.js` | The PC's `rules` subcommand and modlog post, plus GitHub's escalation call. |
| `lib/dashboard-auth.js` | The PC's storage (sessions keyed by **hash** of the token, sign-in events, `.env` setup). GitHub's `listForUser`/`revokeById`/`revokeOthers` were rewritten on top of `listSessions`/`revokeSession`. Short ids are now hash prefixes. |
| `lib/control-server.js` | Static files: classic files from `public/`, then the new dashboard from `dashboard/build/`, then the SPA fallback for extension-less paths. `/` is the new dashboard when built, unless `PANEL_HOME=classic`. Old `/v2/*` redirects to `/*`. The OAuth callback is the PC's version (events, ban screen); `next: 'app'` is set when the new dashboard starts sign-in (it sends `{ redirect }`), and sends you back to `/`. |
| `index.js` | Join handler: `checkJoin` (raid/alt gate) then auto-roles, except for kicked, banned or quarantined members. Rate limits come from `client.rest` `rateLimited` (v14) and also go to `ops.recordRateLimit`. Weekly stats + system monitor + GitHub feed + live alerts all kept. |
| `public/legacy/*` | Moved back to `public/`; the PC's add-ons (`panel-extras.js`, `login-gate.js` and more) load them from there. Git had applied the PC's edits to the moved files, so nothing was lost. |
| `lib/setup-templates.js` | Three Pixel Backrooms rule texts used `'...you've...'`, which broke the whole file (the crash on Pterodactyl). Now double-quoted. |

## Found after merging

- **Slash command limit.** 117 commands, 107 of them per-server. Discord rejects a
  whole set over 100, so no commands would have appeared. `lib/command-deploy.js`
  now sends the first 100 per server and the rest globally with
  `contexts: [0]`, `integration_types: [0]` (server only, same behaviour). There's a
  test for this. If you add many more commands, consider merging small ones into
  subcommands.
- `client.setMaxListeners(30)`: there are 11+ `ClientReady` start-up tasks now.
- The old `checkRaid` test was rewritten for `checkJoin`. `checkRaid` is kept as an
  alias that reports whether raid mode is on.

## Verified

- `node --check` on every server file; all 241 tests pass (3 skipped).
- Booted without a token: `/api/health`, the classic dashboard and its add-ons,
  `/listen`, `/status.html`, the new dashboard at `/` with client routes
  (`/leveling`), and immutable `/_app/` caching.
